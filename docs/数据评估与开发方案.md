# BBallGMDraftClasses 数据评估 & 篮球生涯模拟开发方案

> 评估对象：`BBallGMDraftClasses-main/`（156 文件 / 24.8 MB）
> 结论：**可以作为"世界与球员池"底座，但不能作为"生涯模拟引擎"。核心引擎必须自建。**

---

## 一、可直接复用的资产

| 资产 | 规模 | 用途 |
|---|---|---|
| 逐年联盟快照 | 77 个赛季（1950–2026） | 世界状态底座，NPC 球员池 |
| 球员-赛季记录 | 24,963 条 | 球员池、能力分布基准 |
| 唯一球员 | **4,786 人**（按 `srID` 串联） | NPC 生涯库 |
| 能力维度 | 16 项，值域 [25,100] | 与自定义球员同一把尺子 |
| 球队 | 8 → 30 支（57 个历史队名） | 年代扩张、球队沿革 |
| 选秀班 | 76 届 / 3,038 人 | 新秀标定 + 选秀逻辑 |
| 新秀 OVR/POT | 3,038 个带标签样本 | 校准自定义球员初始能力 |
| 伤病字段 | Healthy / Torn Ligament | 伤病系统雏形 |
| 合同 | 全量覆盖 | 薪资系统雏形 |
| 年代参数 | gameAttributes（工资帽/三分倾向/节奏…） | **天然的"年代难度"来源** |
| 报告文件 | 9348 行，含逐年 OVR 曲线 | 成长曲线的真实标定数据 |

## 二、关键数据事实（开发必须知道）

1. **`pid` 不可用作主键** —— 它是每个文件内 0..N-1 的重新编号（已验证 77 个文件全部如此）。
   **唯一稳定主键是 `srID`**（Basketball-Reference 风格，如 `jordami01`），24,963 行覆盖率 100%，串联出 4,786 人。
2. **`base_leagues` 的评分里没有 `ovr`/`pot`**，只有 16 项属性；`ovr`/`pot` 只存在于选秀班文件。
3. **选秀年 ≠ 新秀赛季**：1950–1984 届的 rating season 等于文件名年份；1985 届之后晚 1 年。
   即 `1996draft.json` 里的评分是 **1997 赛季**的状态，不是 1996。解析时需 +1 年修正。
4. **选秀班覆盖不全**：现代赛季约 38% 的球员无选秀记录（落选秀 + 国际球员，如 Bogdan Bogdanović）。
   自定义球员若落选，必须有独立的入场路径。
5. **`ovr` 无法从 16 项属性反推**：用 3,038 个样本做线性拟合，全局 RMSE=0.89、max|err|=5.37；
   按位置分别拟合（PG/SG/SF/F/C…）仅小幅改善（RMSE 0.32–0.89），max|err| 仍达 0.72–4.54。
   → 说明 OVR 是引擎内部按位置、非线性计算的。**必须自建 OVR 公式**，用选秀班样本回归校准。
6. **年代评分尺度差异巨大**：1950 年顶级球员 OVR ≈ 40–56，1990s 峰值 88。
   → 全明星/最佳阵容等荣誉**必须用"当季联盟内排名/百分位"判定，绝不能用固定 OVR 阈值**，否则早期年代玩家永远拿不到荣誉。
7. **数据脏点（量小但需容错）**：420,015 个属性值中 233 个为 0（占 0.055%），
   集中在 `hgt`(41) / `stre`(104) / `reb`(40) 等；例：Spud Webb、Muggsy Bogues 全部赛季 `hgt=0`。
   正常值域下限为 25（偶见 4），**0 应视为缺失值**，读取时兜底。
8. **2026 赛季是预测值**，不是史实（LeBron 2026 年 42 岁仍在役）。游戏内应标注为"未来/预测赛季"。

## 三、缺失的部分（生涯模拟的核心，全部要自建）

| 缺失项 | 影响 | 自建方案 |
|---|---|---|
| 单赛季数据（得分/篮板/助攻/命中率） | 玩家看不到"我场均多少分" | 由 16 属性 + 出场时间 + 年代参数推导 |
| 荣誉体系（全明星/MVP/最佳阵容/DPOY…） | 生涯没有里程碑 | 按当季联盟内排名分配 |
| 季后赛与总冠军 | 生涯没有最高目标 | 球队战力 → 战绩 → 季后赛对阵树 |
| 年龄字段 | 无成长/衰退曲线 | `赛季年 - born.year` 推导 |
| 球员发展曲线 | 属性怎么涨 | 用报告 C4 的真实 OVR 曲线标定 |
| 退役/HOF 判定 | 生涯没有终点 | 年龄 + 状态 + 荣誉积分 |
| 事件系统 | 生涯平淡无故事 | 伤病/交易/合同年/更衣室/媒体 |
| 生涯存档 | 无法续玩 | 自定义球员 + 逐年结果落库 |

**根本原因**：这 77 个文件是**每个赛季的"输入状态"**（开季名单），不是"模拟输出"。
它们描述"那个年代联盟长什么样"，不描述"某个人经历了什么"。而生涯模拟要的恰恰是后者。

## 四、数据模型建议

```
Player(pid 自增)          -- 自定义球员 + NPC，统一表
  srID?                   -- 真实球员才有，用于关联原数据
  isUser: bool
  pos, hgt, weight, bornYear, bornLoc, college

PlayerSeason              -- 逐年记录，唯一主键 (playerId, season)
  season, teamId, age
  attr_* (16 项)          -- 每年一份快照
  ovr, pot                -- 自建公式算出
  stats_*                 -- 自建模拟产出
  injury, contract

Career                    -- 生涯汇总
  seasons, totals, peaks, awards[], championships[], hof

League(season)            -- 逐年世界状态
  teams[], salaryCap, threePointTendencyFactor, pace ...
```

**关键设计**：把 `base_leagues` + `draftclasses` 预先 ETL 成一张
**以 `srID` 为键的球员-赛季时间序列表**（24,963 + 3,038 行）。
这一步做完，后面所有系统都只是在这张表上做查询和写入。

## 五、落地路线

- **Step 1（1–2 天）ETL**：77 + 76 个 JSON → 球员-赛季时间序列表；处理 0 值、选秀年 +1、`srID` 主键。
- **Step 2（2–3 天）OVR 公式**：用 3,038 个带标签样本拟合（按位置），目标 RMSE < 1.5；输出可复用函数。
- **Step 3（3–5 天）生涯循环 MVP**：自定义球员 → 选秀 → 逐年模拟（成长/衰退 + 球队 + 数据 + 荣誉）→ 退役 → 生涯总结。
- **Step 4（迭代）事件系统**：伤病、交易、合同谈判、季后赛、历史地位。

**建议首个年代选 1984–2026**：现代数据最完整、球队体系稳定（30 队）、玩家认知度最高。

## 六、法律与风险

- 仓库**没有任何 LICENSE 文件**（已验证无 LICENSE / COPYING / .git）。
- 球员姓名为真实姓名，`srID` 沿用 Basketball-Reference 命名体系；数据格式源自 Basketball GM。
- **自用/学习无碍；一旦商业化，姓名权与数据来源授权是硬风险**，需换用虚构球员池或取得授权。
- README 自述"仍在开发中，部分球员身体数据与评分可能不准确"。
