# 篮球人生 · Hoop Life

文字式篮球生涯模拟游戏。自定义球员 → 任选年代开局 → 属性加点成长 → 退役结算。

对标虎扑《我创造的完美球员》的玩法形态，但**支持从任意年代开始**（1950–2026，共 77 个赛季）。

---

## 快速开始

```bash
npm install
npm run etl:players   # 生成球员池（首次必须执行）
npm run dev           # 启动开发服务器
```

其他命令：

```bash
npm run etl:check     # 校验球员池（数据层验收脚本）
npm run build         # 打包成静态站点
npm run preview       # 预览打包结果
```

## 数据管线

原始数据是 Basketball GM 的联盟存档与选秀班，**不是**可直接使用的游戏数据。
`npm run etl:players` 做四件事：

### 1. 建立稳定主键

源数据里每个文件内的 `pid` 都是 `0..N-1` 重新编号的（乔丹 1991 年是 pid=50、1996 年是 pid=59），
**不能当主键**。改用 `srID`（Basketball-Reference 风格，如 `jordami01`）跨赛季串联，
24,963 条球员-赛季记录归并出 **4,786 名唯一球员**。

### 2. 年代归一化（最关键的一步）

原始属性在不同年代尺度完全不同：1950 年代顶级球员 OVR 只有 40–56，1990 年代峰值 88。
直接使用会导致"从 1950 年开始玩"的角色弱到无法游戏。

处理方式：**赛季内全局百分位 → 幂曲线收中段 → 映射到 [25,99]**。
每个年代因此自成一个完整的强度体系，中位数统一在 61–62、最高值统一在 95–99。

### 3. 推导 13 项游戏属性

源数据是 16 项 Basketball GM 属性，游戏用 13 项（对齐虎扑的键名）：

| 游戏属性 | 推导来源 |
|---|---|
| threePT 三分 | `tp` |
| MID 中投 | `fg` × 0.85 + `ft` × 0.15 |
| FIN 终结 | `ins` × 0.65 + `dnk` × 0.35 |
| DNK 扣篮 | `dnk` |
| HAN 护球 | `drb` × 0.85 + `spd` × 0.15 |
| PAS 传球 | `pss` |
| PDEF 外防 | `diq` × 0.6 + `spd` × 0.4 |
| IDEF 内防 | `diq` × 0.6 + `stre` × 0.4 |
| BLK 盖帽 | `hgt` × 0.5 + `jmp` × 0.3 + `stre` × 0.2 |
| REB 篮板 | `reb` |
| ATH 运动 | `spd` × 0.5 + `jmp` × 0.5 |
| STR 力量 | `stre` |
| CLU 关键 | `oiq` × 0.6 + `endu` × 0.2 + `ft` × 0.2 |

### 4. 计算 OVR

`OVR = Σ(属性 × 位置权重)`，再按当季分位套统一锚点
（`p50→62, p90→82, p97→91, p100→99`），保证"≥95 超级巨星"这类档位在每个年代同样成立。

## 数据层踩过的坑（改管线前务必先读）

| 坑 | 现象 | 处理 |
|---|---|---|
| `pid` 不稳定 | 同一球员在不同赛季 pid 不同 | 用 `srID` 作主键 |
| 选秀年 ≠ 新秀赛季 | 1985 届之后，选秀班文件里的评分年份比文件名晚 1 年 | 选秀班用**文件名年份**做键；`2024draft` 与 `2025draft` 的 `startingSeason` 都是 2025，用后者会丢一届 |
| 0 值属性 | 420,015 个属性值中 233 个为 0（Spud Webb、Muggsy Bogues 全部赛季 `hgt=0`） | 视为缺失，用赛季中位数兜底 |
| 按位置组归一化 | 每组中位数都归到 0.5，导致所有位置所有属性均值都变成 62，中锋篮板和控卫一样 | **属性用赛季内全局百分位**，位置特征交给 OVR 权重表达 |
| 小样本位置组 | 2020 赛季只有 6 名 PF，Giannis 在 6 人组里样样第一 → 属性虚高到 99 而 OVR 只有 81 | 同上；另，不要按位置组做 OVR 中位数校准（该组中位数不稳定） |
| 泛化位置标签 | 源数据用 `F`/`GF`/`FC`，`F` 占 10–17%，简单归到 SF 会让 SF 占联盟 44% | `F` 用 SF/PF **混合权重**，`FC` 用 PF/C，`GF` 用 SG/SF |
| 身高是位置决定项 | 用全局百分位会让"高个子"等价于"中锋" | `hgt` 单独按位置组归一化 |
| 内线被系统性低估 | 初版权重下 2020 赛季前 10% 只有 4 名中锋（占联盟 17%），Shaq 2000 年排第 27 | 重标定 C/PF 权重：大幅提高 FIN/IDEF/REB/BLK/STR，压低 threePT/MID/HAN/PAS |
| 源数据噪声 | 张伯伦 1962 年 `diq=55`（明显偏低） | 验收用"当季百分位"判据，不用绝对分数阈值，避免为噪声过拟合 |

## 玩法设计要点

- **属性加点**：建号时给固定点数自由分配，成长靠赛季间的加点，**不抽取球员能力**
- **夺取属性**：作为特殊奖励机制出现（触发条件待定），而非建号主流程
- **年代选择**：可选任意具体年份开局（1950–2026），年代决定联盟规模、球队沿革、规则参数
- **AI 互动**：文字占体验大头，预留 AI 接入位（见 `src/game/`），用于事件叙事与个性化点评

## 明确不做

商店 / 装备 / 开箱、体力条与广告、多难度模式、全明星周末小游戏、深度球队经营。
